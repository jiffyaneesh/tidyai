# 07 — Agent instruction files

Question: what belongs in `AGENTS.md` and `CLAUDE.md`, and how SOLID, KISS, and the UI rules get in without making the files ignored.

Date: 2026-11-06.

## Evidence

`AGENTS.md` is a README for agents. The spec at [agents.md](https://agents.md/) requires no sections. It asks for what a new teammate would need: how to run the project, how to test, and the boundaries. Nested files are for packages whose rules differ. This repo is small enough for one root file.

[Claude Code's memory docs](https://code.claude.com/docs/en/claude-md) and the [Claude help article on CLAUDE.md](https://support.claude.com/en/articles/14553240-give-claude-context-claude-md-and-better-prompts) say the file is loaded every session, so every line costs attention. They target under about 200 lines. Instructions should be concrete enough to check ("run this command") rather than slogans ("write clean code"). They tell you to leave out file trees, changelogs, and rules the code already makes obvious. [Best practices](https://code.claude.com/docs/en/best-practices) say a line the model keeps ignoring is either buried in a long file or belongs in a hook, not in more emphasis.

A survey of public files ([diffox](https://diffox.ai/blog/agents-md-vs-claude-md)) found a median around 92 lines, and that repos which have both files often make `CLAUDE.md` a one-line `@AGENTS.md` import so the rules cannot drift. Claude Code still loads an import into the session ([large-codebase guide](https://code.claude.com/docs/en/large-codebases)), so the import does not save tokens. It does keep a single copy. The [AAIF note](https://aaif.io/blog/writing-an-effective-agents-md) says the useful content is the constraint the agent cannot see from filenames: which layer may import which, and the exact test command. [Atlan's how-to](https://docs.atlan.com/agents/how-tos/write-an-agents-md-file) adds the failure mode we are avoiding: an autogenerated essay, two files that disagree, and a boundary written as "be careful."

Confidence: **high** that Claude Code and the AGENTS.md spec describe this loading behavior. **Medium** on the line-count surveys. They are other people's samples, not a measurement of this repo.

## Decision

`AGENTS.md` is the only copy of the rules. `CLAUDE.md` imports it and adds three session notes that are easy to miss: how the schema is applied, that a UI change needs a browser pass, and which slices are not open work.

SOLID, KISS, and the UI research are written as checks, not as definitions.

| Principle | What an agent can do with it here |
| --- | --- |
| Single responsibility | Agent code does not open SQL. API code does not own prompt text. The web app does not rank chunks. |
| Open/closed | A new OpenAI-compatible host is settings. A new wire protocol is a branch in `stream_chat`. |
| Liskov, in practice | Provider failures cross the API boundary only as `ProviderError`, with secrets already redacted. |
| Interface split | The turn JSON has no key. The key is one header. |
| Dependency direction | API calls the agent. The agent does not import FastAPI or psycopg. |
| KISS | No framework, no second migration tool, no third protocol, until the current shape cannot say the thing. |
| UI | Tokens, contrast, motion, Streamdown versus block views, and the overlay Close control. The essays stay in `docs/research/01-chat-interface.md` and `02-render-engine.md`. |

A textbook paragraph in `CLAUDE.md` would be loaded on every session and would not change a diff. The research files already hold the arguments.

## What would change this

- The same mistake twice, and the rule is missing. Add one checkable line to `AGENTS.md`.
- `AGENTS.md` passing roughly 250 lines. Move the extra into `docs/research/` or a nested file for the package that needs it.
- Claude Code stopping `@` imports. Then copy the rules into `CLAUDE.md` once, and delete the import, still without keeping two editable copies.
